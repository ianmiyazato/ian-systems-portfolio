# Ian Miyazato · systems portfolio

Product/design execution, frontend craft and distributed-systems judgement, shown as three running (fictitious) platforms.

**Production: https://ian-portfolio-shell.vercel.app**

> **Try it with the Decision Lens: press `D`** on any screen (or click **Show decisions**). Numbered hotspots pin to the UI; each opens the decision, why, the alternative considered and the reviewer value. Press `⌘K` / `Ctrl+K` to jump to any of the 77 screens, control the shared world clock, run a screen action, or inject a chaos scenario.

## Measured quality

Lighthouse 12.6.1 (mobile, median of 3) on local production builds, 2026-09-28: performance **95** home · **99** shop · **100** Counter · **90** Tidewatch · **97** Pulse; accessibility and best practices **100** on all five. Playwright passes **585/585**, including every manifest route and nav item, **77/77** Decision Lens anchors, reduced motion on all 77 routes, and 40 JavaScript budget checks. axe (WCAG 2.1 A/AA): **166/166** route and variation targets with zero serious or critical issues.

## System design in 15 minutes

[/system-design?present=1](https://ian-portfolio-shell.vercel.app/system-design?present=1) plays two problems end to end in plain language, with the engineering behind each step one key away (`E`):

- **Problem A · turning a flood of numbers into decisions** · a results file every minute is checked, stored, compared to normal and explained by AI in a one-page morning report, and a checker verifies every number the AI writes.
- **Problem B · personal, and still instant** · suggestions a shopper can actually get, a speed race on one clock, and a live demo that pages 2,000 products in your browser with a simulated AI slot and an 800 ms fallback.
- **The 80/20 map** · every build-or-buy choice from both problems, generated from the same JSON as the cards, each with what we give up.

Arrows walk the steps across pages, `N` shows the presenter notes, and the talk track is [docs/CALL-SCRIPT-SYSTEM-DESIGN.md](docs/CALL-SCRIPT-SYSTEM-DESIGN.md).

## Reviewer tour: chaos → trace → fix → recover

1. **See how orders stay safe** · [/system-design/mare](https://ian-portfolio-shell.vercel.app/system-design/mare): step through write once, one feed, a slow partner failing alone, and replay.
2. **Inject chaos from anywhere** · press `⌘K` / `Ctrl+K`, run **Chaos: saturate the Orders DB pool**, then open [Tidewatch Problems](https://ian-portfolio-shell.vercel.app/observability). The same fault opens the circuit in Mesh, slows Pay scoring and warns Counter.
3. **Follow the evidence** · open [trace `9f3a2c`](https://ian-portfolio-shell.vercel.app/observability/traces/9f3a2c): the waterfall highlights the DB wait, the deploy marker lines up with the regression, and logs are correlated by trace id.
4. **Fix it** · return to [problem P-812](https://ian-portfolio-shell.vercel.app/observability) and choose **Roll back #812** or **Raise pool to 64**. The action creates its own trace with a **View trace** link.
5. **Watch recovery** · the red problem becomes **All clear**, latency and saturation recover, the SLO stops burning, and every open zone receives the same world event.
6. **Inspect the craft** · press `D` on any stop, then visit the [v0.2 improvement map](https://ian-portfolio-shell.vercel.app/work/v0-2) for all 12 changes and direct links.

Then sample the product breadth: [Counter returns](https://ian-portfolio-shell.vercel.app/mare/ops/counter/returns), [Pay disputes](https://ian-portfolio-shell.vercel.app/mare/ops/pay/disputes), [the Maré shop](https://ian-portfolio-shell.vercel.app/mare/shop), [Atlas Practice Mix](https://ian-portfolio-shell.vercel.app/atlas/arena/mix/today), and [Pulse Audio Intelligence](https://ian-portfolio-shell.vercel.app/pulse/audio/afterglow).

## Architecture

```text
                        https://ian-portfolio-shell.vercel.app  (one domain)
                                         │
                       Next.js 15 shell · beforeFiles rewrites (env-driven)
      ┌───────────────────────┬──────────┴──────────────┬───────────────────────┐
      │ / · /work · /atlas    │ /mare/ops/*             │ /mare/shop · /mare/apps│ /pulse/*
      │ /observability        │ Vite + React host       │ /system-design (story) │ SvelteKit
      │                       │  └ runtime federation   │ Astro (static, islands)│ EN/KR/JP
      │                       │    remotes.config.json  │                        │
      │                       │    → mf-manifest.json ×5│                        │
      │                       │    Counter · Product Hub│                        │
      │                       │    Pay · Circle · Mesh  │                        │
      └───────────┬───────────┴────────────┬───────────┴────────────┬──────────┘
                  │  shared packages: tokens (9 themes) · chrome web components
                  │  (<im-portfolio-bar>, <im-decision-lens>, <im-command-palette>)
                  │  overlays · ai-surface · ai-sim (AIProvider) · events · world
                  └──────────── seeded browser simulation + optional Supabase Broadcast
```

- **Four independently deployed zones** composed with Next.js multi-zone rewrites; each zone builds its output under its own URL prefix.
- **Runtime federation inside Maré Ops**: five Preact remotes, each with its own theme, fonts and chrome, loaded from manifests at runtime behind per-remote error boundaries.
- **One token contract, nine themes**, AA contrast enforced by a unit test; **one AI trust surface** everywhere.
- **URL-addressable overlays**: any nested modal, drawer or sub-layer is a deep link.
- **One deterministic browser world** drives live events, traces and incidents across every stack; BroadcastChannel is the default transport, while explicit opt-in Supabase Broadcast demonstrates cross-device sync.
- **Simulated AI** behind the same `AIProvider` interface a live model uses, with sources, tool latency, model route, eval score, tokens, cost and a shared approval audit.

## Run it locally

```bash
corepack enable && corepack prepare pnpm@10.17.1 --activate
pnpm install
pnpm dev            # all four zones; open http://127.0.0.1:3000
pnpm check          # lint, typecheck, unit tests, build
pnpm build && pnpm e2e          # Playwright: flows, Decision Lens anchors, axe on every route
pnpm build && pnpm screenshots  # regenerate docs/screenshots, then: node scripts/readme-gallery.mjs
```
